# Граф и отсечка

Граф — своя реализация по архитектурной идее прототипа. Индекс строится по
публичной истории PostgreSQL, ответы проверяемы (revision, path, SHA-256, byte
span), отрицательные результаты сохраняются.

## Временная отсечка

Cutoff задаётся одновременно `base_sha` и его commit time. Любая возвращаемая
revision обязана быть предком `base_sha`; одной проверки timestamp недостаточно,
потому что часы коммитов не монотонны по времени.

- Множество reachable-коммитов вычисляется от `base_sha`.
- `head_sha` исключается из множества и никогда не выдаётся.
- Потомки `base_sha` (включая `head_sha` и его patch) не индексируются в сессию.

## Инструменты

Слой v1 работает по локальному индексу (250 последних коммитов):

- `find_code_symbols` — поиск символов C-кода по имени до cutoff.
- `read_versioned_source` — метаданные файла на закреплённой ревизии с SHA-256
  и byte span.
- `search_git_history` — поиск по сообщениям коммитов и hunks.

Слой v2 работает по производному `history.sqlite` с полной цепочкой `parents`:

- `symbol_history` — как менялся один символ во времени.
- `tests_to_code` — какой production-код менялся вместе с данным тестом.
- `similar_fixes` — прошлые коммиты со схожим интентом.
- `find_error_origin` — где печатается заданное сообщение об ошибке.

Описания v2 сформулированы «по ситуации»: сначала когда инструмент нужен и когда
его можно пропустить, и лишь потом — сигнатура. Ручка `graph` подключает оба слоя,
`graph_v2` — абляция: три инструмента v1 выключаются в конфиге OpenCode
(`"tools": {"graph_find_code_symbols": false, ...}`), у агента остаётся только
слой истории.

Каждый ответ несёт revision, path, SHA-256 и cutoff metadata. Нулевой результат
пишется в audit log.

## Подключение к OpenCode

MCP подключается как remote Streamable HTTP (`http://graph:8765/mcp`) с
увеличенным timeout. Эффективный OpenCode-конфиг генерируется на каждый run:
bare-конфиг MCP не содержит, graph-конфиг подключает сервер графа; hash конфига
пишется в manifest. В graph-промпте явно перечислены доступные инструменты;
`graph_v2` не упоминает выключенные v1-инструменты, чтобы агент не звал
недоступное. Ноль обращений к MCP в graph-run считается ошибкой интеграции, а не
результатом эксперимента.

Абзац про историю имеет два варианта формулировки (`--prompt-variant`):

- `directive` — «Before editing, use the MCP tools»: инструменты обязательны
  перед правкой;
- `situational` — «Start editing as soon as you have localized the cause»:
  инструменты доступны по необходимости, правку можно начинать раньше.

Вариант пишется в manifest (`prompt_variant`) и в run record, поэтому эффект
формулировки промпта не смешивается с эффектом состава инструментов при разборе
отчёта.

## Index и probe

- Union-индекс строится по последним 50 предкам каждого из пяти `base_sha` и
  дедуплицирует blobs/symbols. Дельта коммитов дополняется **снимком полного
  source-дерева каждой базы**: файл, который в последних 50 коммитах не менялся
  (например, `relnode.c`), всё равно должен быть доступен агенту для чтения.
  Bytes дедуплицируются по SHA-256, поэтому снимок не растёт линейно.
- Индекс передаётся в graph-container копией SQLite, полный git-клон в контейнер
  не монтируется.
- Cutoff вычисляется по parent graph индекса, без доступа к git-клону.
- Дешёвый E2E probe (`benchmark probe`) запускает MCP-клиент внутри самого
  graph-container: `initialize`, `list_tools`, по одному вызову каждого
  инструмента и отказ по `head_sha` текущей задачи. Отдельный режим
  `probe_client URL HEAD_SHA` проверяет только cutoff и вызывается из graph-run.

## Adversarial tests

Проверяется, что запрос точного `head_sha`, symbol/history после cutoff и чтение
непредковой revision возвращают отказ или пустой результат.
