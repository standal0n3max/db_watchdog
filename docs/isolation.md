# Изоляция прогона и anti-leak boundary

Задача выполняется в одноразовом контейнере без bind mounts. Данные, клон,
эталон и результаты на хосте не монтируются: `docker inspect` должен показать
`Mounts == []`, иначе прогон не засчитывается.

## Контейнер

- `docker create --init -i` с `--cap-drop ALL` и `--security-opt no-new-privileges`.
- Образ объявляет `USER bench`, контейнер создаётся с `--user bench`: и PID 1, и
  каждый `docker exec` работают непривилегированно.
- Ограничения CPU/memory/pids и гарантированное удаление через `docker rm -f`.
- Дерево `head_sha` передаётся архивом через `docker cp`/stdin, а не монтированием.
- Payload и патчи пишутся в `/work` через stdin.
- OpenCode работает непривилегированным пользователем в `/workspace/postgres`.

## Сеть

- Task-container подключён только к внутренней сети `bench-internal`.
- model-gateway — единственная точка, где живёт ключ OpenRouter. Он подключён
  одновременно к внешней и внутренней сети.
- Task-container получает только `POSTGRES_GYM_PROVIDER_KEY` как ключ провайдера
  и никогда не видит `OPENROUTER_API_KEY`.
- В режиме `graph` контейнер задачи дополнительно видит MCP-контейнер графа.

## Порядок до запуска агента

1. На хосте развернуть дерево `head_sha` из локального клона и применить к нему
   reverse source patch: получается buggy-исходник. Эталонный патч на хост не
   покидает, в контейнер уходит уже готовое дерево.
2. Упаковать дерево в архив без `.git` и скопировать его в контейнер через
   `docker cp`; bind mounts не используются.
3. Дождаться маркера `/work/ready`: entrypoint распаковал архив.
4. Сделать configure и prebuild/install, чтобы мутация собиралась.
5. Удалить все тестовые `.sql`/`.out`/`.spec` и варианты `_N.out`.
6. Оборвать историю: заменить `.git` новым репозиторием с одним
   baseline-коммитом, без remotes и reflog. После этого `git show <head_sha>`
   завершается ошибкой.

## После агента

1. Вернуть скрытые тесты.
2. Проверить gate-ы: непустой source diff, запрет изменений `src/test`,
   отсутствие пересозданных скрытых тестов.
3. Выполнить build/install, targeted тесты и полный regression.
4. Посчитать verdict: gate-ы пройдены, целевой тест прошёл, неожиданных
   regression-падений нет.

## Что не попадает в git

`data/` целиком игнорируется: задачи, oracle, prep, клоны, прогоны, индекс
графа, журналы. Секреты приходят только переменными окружения; `.env` не
читается кодом benchmark.
